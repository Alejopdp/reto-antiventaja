Reto Antiventaja — Mapa del MVP

Plan high-level para la reunión · 2026-07-01 · documento de lectura previa

Un “cerebro” propio que orquesta un embudo de educación financiera por WhatsApp: un reto gratuito de 7 días que convierte al plan pago P60 (60 €), con seguimiento 1:1 asistido por IA, captura de prueba social y atribución de referidos. Arquitectura hexagonal (agnóstica del canal): las herramientas externas (GHL, WhatsApp, vídeo, pago, IA) viven detrás de “puertos” intercambiables. Mercado España, single-tenant (para BeZy).

1 · El recorrido — qué hace el sistema

Recorrido del participante

  1. Registro (formulario) → crea contacto + participante.
  2. Verificación — Ops acepta/rechaza (gate humano).
  3. Alta al grupo (manual) + bienvenida 1:1 (automática).
  4. Reto 7 días — contenido diario (grupo: manual · 1:1: auto) + seguimiento 1:1 con IA.
  5. Directo dominical (Zoom) = la venta — se mide la asistencia.
  6. Replay 1:1 tokenizado → segmentación → follow-ups.
  7. Pago P60 (Stripe/Bizum) → convertido + atribución.
  8. Prueba social (form tipado + evidencia, moderada) → dashboard público.

Operación interna (equipo/Ops)

  • Verificar inscriptos · bloqueo permanente
  • Gestionar cohortes (crear/estado)
  • Cola de mensajes: reintentar / reenviar acceso
  • Resolver atribución (quién invitó)
  • Dar de baja
  • Tomar la conversación (takeover de la IA)
  • Moderar prueba social (aprobar/ocultar)
  • Recibir alertas de inacción + reprogramar
  • Componer el mensaje del día para el grupo

26 casos de uso en total (UC-01…UC-26; detalle en use-cases.md).

2 · Arquitectura (alto nivel)

El CEREBRO (propio) — dueño del dominio: event log + estado, lógica del reto, segmentación, atribución, dashboards. (Next.js + PostgreSQL, hexagonal.)

…habla con el mundo exterior solo a través de puertos (piezas intercambiables):

Mensajería / CRM → GHL (contacto + 1:1) · Kapso (grupos, diferido)
Vídeo → página propia tokenizada + host commodity (Cloudflare Stream)
Pago → Stripe / Bizum
IA → motor del agente (ver §3)

regla clave el cerebro es dueño del dominio (cohorte, estado, segmentación, atribución); GHL es dueño del contacto y las conversaciones. Sincronización en una dirección (empujamos datos de display a GHL) + webhooks de GHL hacia el cerebro. No se duplica la verdad.

3 · La gran decisión: ¿quién corre la IA? Q58 — para la call

El seguimiento 1:1 lo lleva un “agente guarded”: responde solo dentro de un menú acotado del reto (no se va de tema), y un humano puede intervenir en cualquier momento (la IA se pausa). Lo decidido: la IA responde sola con supervisión humana (se descartó “humano envía cada mensaje”: no escala). Falta decidir quién la GENERA — y de esto cuelgan varias decisiones:

OpciónQué implicaA favor / En contra
A · Agente propio Lo construimos nosotros (nuestro cerebro + un LLM): prompt, tools, contexto de dominio completo. ➕ Control total, cualquier modelo, respuestas ricas.
➖ Construimos agente + chat + takeover.
B · Agente de GHL
(Agent Studio)		 Le damos prompt + base de conocimiento + “custom actions” que llaman a nuestro cerebro para el contexto (día, tareas…). ➕ Managed, takeover nativo, lo edita el equipo.
➖ Límites (≤10 tools, LLM de GHL), lock-in + coste.
C · Híbrido GHL corre la conversación y el takeover; el cerebro le da contexto y recibe señales. ➕ Menos build, aprovecha lo nativo.
➖ Reparte responsabilidades (coordinación).
Para la call: la decisión depende de qué se espera de GHL (¿solo CRM, o reusar embudos/membresía ya montados?) y de cuánto priorizan control/inteligencia (→ propio) vs rapidez y edición por el equipo (→ GHL/híbrido). Nota: “generar” la respuesta (la inteligencia) es distinto de “entregarla” (mandar el WhatsApp); entregar lo hace GHL/Kapso en cualquier caso.

4 · Cómo lo partimos — entregas

Pensado desde el final hacia atrás: fases que entregan valor por sí solas.

Fase 0 · Esqueleto — registro → verificación → alta (manual) → contenido básico. Prueba el flujo de punta a punta.
Fase 1 · Motor de conversión — directo Zoom (asistencia) + replay tokenizado + medición propia + follow-ups segmentados + pago/atribución. El corazón del producto.
Fase 2 · Agente IA 1:1 + takeover — escala el seguimiento (fue lo que subió la conversión ~20%→40%). Depende de Q58.
Fase 3 · Prueba social + dashboard público + inacción/reprogramación — motivación y optimización.
Transversal — integración con GHL y configuración de contenido editable por el equipo.
